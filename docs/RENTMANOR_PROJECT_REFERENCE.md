## Current implementation and conservative defaults

Static JavaScript/HTML/CSS PWA in app/, marketing in site/, Supabase Auth/Postgres/private Storage, Netlify and historical GitHub Pages fallback remain. No framework rewrite/custom server, payments, rent collection, full accounting, maintenance tickets, tenant portal/history, MLS service or native app was added. Call/Text/Email launch device handlers; correspondence is a saved copy, not a mail integration.

Account content tables: properties, expenses, receipts, property_photos, property_appliances, tenants, tenant_files. Accounts/memberships/invites are access administration, not imported recovery authority. Same-account composite FKs and RLS are the security boundary. Owners/members are trusted editors with delete/complete-restore rights; only owners manage invitations. Sample account 00000000-0000-4000-8000-000000000001 remains public/read-only, with canonical homes ending 011/012/013. Personal accounts are never seeded from it.

Recovery JSON v2 contains all seven tables, referenced image/PDF bytes, export time/counts and SHA-256 hashes. Snapshot RPC returns canonical rows plus a revision; export checks that revision again. Limits are 5,000 homes/50,000 rows per table/70 MiB binaries/100 MiB JSON/10 MiB per archive object. Missing/inaccessible/unsupported files fail completeness. Restore validates scope/IDs/parents/paths/counts/hash/cover, previews, saves a verified current recovery point, requires REPLACE, registers a two-hour user/account-scoped incoming-property stage, uploads fresh recovery paths and downloads them to verify, then atomically replaces rows only at the expected current revision. Failed new paths are compensated; originals and interrupted leftovers remain for scoped operator recovery/cleanup. Existing updated_at audit values can change through normal database synchronization triggers; business fields/IDs/created_at and bytes remain the recovery comparison. No automatic retention schedule or garbage collector exists.

Legacy restore RPC now merges supported property fields and never deletes omitted records/children; fingerprints deduplicate retries under an account lock. UI limited imports reject conflicting existing IDs, use fresh IDs and do not import legacy paths as file recovery. Similar addresses do not prove identity. Browser legacy source is retained.

Signup trigger creates only a personal owner account and never consumes untrusted token metadata. Confirmed auth.users email drives accept/claim. Invites have high-entropy 64-hex tokens, 14-day expiry, optional target email, revocation and accepted_by; a row lock consumes once, same accepted identity can retry safely. Short legacy tokens are revoked; owners manually reissue without automatic email. lookup exposes only generic account label/status. Platform rate limits need provider verification.

Optional clearing uses null for numeric/path fields and empty text for text, while absent fields remain absent; zero is preserved. Compatibility stripping retries and silent truncation were removed. Tenant save/vacate, vacancy status transitions and primary selection have transactional server behavior. Gallery cap locks the property; one receipt/expense is unique. Referenced media must be present in the private bucket and scoped to its exact account/property. Storage delete/update prevents removal/overwrite while referenced. Uploads use new paths and retire originals only after metadata commit; failures retain draft/record IDs and report partial success. Atomic Storage+Postgres transactions are not available; compensation and recovery replace that assumption.

Account selector validates memberships and per-user persisted preferences, clears DOM/maps/drafts/file URLs/permissions, and rejects stale responses. Signout cancels recovery. RLS remains authority; stored account IDs never grant access. Money/date/facts bounds reject blank amounts/excess precision/invalid dates; uploads inspect signatures. Source photos up to 15 MiB are compressed to JPEG up to 450 KiB; normal PDFs max 8 MiB, Storage max 10 MiB, supported JPEG/PNG/WebP/GIF/PDF. Existing unsupported media requires operator recovery/conversion, not silent loss. Client signatures and Storage MIME settings are not universal file-decoder proof.

CSV prepends apostrophes for formula-leading user text even after whitespace/control prefixes; dates/amounts remain useful. PDF embeds Noto Sans through pinned pdf-lib/fontkit, wraps measured text including long addresses/unbroken strings, repeats headers and paginates. Unsupported characters fail with a CSV alternative. Expense reports omit receipt binaries and remain separate from recovery.

app/config.js is the sole browser backend config. No inline production fallback; explicit allowedHosts/environment prevent copied production defaults connecting from localhost. Local tests serve null config and block remote traffic. Public anon configuration remains; no privileged browser credential was introduced. .env.example is not consumed. Worker v24 caches public shell/font/vendor/sample assets only, ignores config/API/signed-file traffic, and replaces prior cache. Private operations need network; no write queue was invented. Build-static curates dist so SQL/tests/node_modules/ZIPs/tmp/private archives cannot be published by the Netlify build.

Pinned additions: pdf-lib 1.17.1, @pdf-lib/fontkit 1.1.1 for maintained Unicode PDF output; dev-only PGlite 0.5.8 and Playwright 1.62.1 for reproducible SQL/browser checks. Vendored notices/font OFL preserved; fontkit published upstream provides README MIT designation without a separate license file. See docs/THIRD_PARTY_NOTICES.md. No paid dependencies/services introduced.
